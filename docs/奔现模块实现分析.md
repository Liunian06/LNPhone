## 1. 功能定位

“奔现”是项目中的沉浸式角色扮演场景功能，也可以理解为“线下模式”或“沉浸模式”。它不是普通聊天窗口，而是把用户与 AI 角色的互动包装成视觉小说 / Galgame 风格的线下见面体验。

核心目标：

- 让用户从普通聊天切换到“和角色线下见面”的沉浸场景。
- 用全屏场景图、旁白、角色对话、动作、心理活动、状态和互动选项构成连续剧情。
- 通过 AI 实时生成开放式剧情，而不是依赖固定脚本。
- 通过场景图生成与缓存，让场景具备可视化、连续性和复用能力。

## 5. 状态管理：ScenarioProvider

### 5.1 文件位置

`lib/core/providers/scenario_provider.dart`

### 5.2 职责

`ScenarioProvider` 是奔现功能的核心状态管理类，负责：

- 初始化奔现场景。
- 加载奔现专用提示词。
- 保存当前消息列表。
- 发送用户输入。
- 处理用户选择的选项。
- 调用 LLM 生成 AI 响应。
- 解析 AI 返回消息。
- 根据 `scene` 消息生成或切换背景图。
- 更新当前位置、时间、天气、角色状态和可选项。
- 过滤出需要在 UI 上展示的消息。

### 5.3 核心状态结构

```dart
class ScenarioState {
  final String? currentSceneImage;
  final String? currentLocation;
  final String? currentTime;
  final String? currentWeather;
  final String? characterState;
  final List<Map<String, dynamic>>? currentOptions;
  final bool isGenerating;
  final bool isGeneratingScene;
}
```

### 5.4 核心调用链路

```text
用户输入 / 点击选项
  ↓
ScenarioProvider.sendMessage() / selectOption()
  ↓
_generateAiResponse()
  ↓
LlmService.generateResponse()
  ↓
ResponseParser.parse()
  ↓
_processMessage()
  ├─ scene     → _handleSceneMessage() → SceneCacheService / ImageGenerationService
  ├─ state     → 更新 characterState
  ├─ options   → 更新 currentOptions
  └─ narration / words / action / thought → 加入展示消息
  ↓
notifyListeners()
  ↓
ScenarioScreen 刷新
```

## 6. AI 交互与提示词系统

### 6.1 专用提示词文件

`assets/prompts/scenario_prompt.txt`

该文件定义了奔现模式下 AI 的角色与输出格式。AI 在该模式中更像“沉浸式场景导演 + 角色扮演者”。

### 6.2 Prompt 要求

当前提示词约束 AI：

- 使用第一人称视角生成场景。
- 输出结构化 JSON 数组。
- 不输出 Markdown 代码块。
- 场景需要适合生成竖屏背景图。
- 根据剧情输出旁白、对白、动作、想法、状态和选项。
- 每轮可提供 3-5 个互动选项。
- 剧情是开放式推进，不依赖固定剧本。

### 6.3 AI 返回格式

```json
[
  {
    "type": "scene",
    "content": "从我的视角看去：对面坐着一个穿白色连衣裙的女孩...",
    "generate": true,
    "location": "咖啡厅",
    "time": "下午",
    "weather": "晴天"
  },
  {
    "type": "narration",
    "content": "她抬起头，目光与你相遇。"
  },
  {
    "type": "word",
    "content": "你...怎么一直看着我啊"
  },
  {
    "type": "action",
    "content": "不自觉地拨了拨耳边的碎发"
  },
  {
    "type": "thought",
    "content": "他一直盯着我看..."
  },
  {
    "type": "state",
    "content": "害羞"
  },
  {
    "type": "options",
    "content": [
      {"id": "1", "text": "握住她的手", "tone": "浪漫"},
      {"id": "2", "text": "移开视线", "tone": "害羞"}
    ]
  }
]
```

### 6.4 响应解析

相关文件：

`lib/core/services/xml_parser.dart`

虽然文件名仍为 `xml_parser.dart`，但当前职责已经包含 JSON 解析和兼容旧 XML 格式。

解析能力包括：

- 移除 Markdown 代码块包裹。
- 尝试解析 JSON 数组。
- 修复部分常见 JSON 格式错误。
- 将 JSON 项转换为 `ChatMessage`。
- JSON 失败时回退 XML 解析。

## 7. 消息类型与数据库集成

### 7.1 沉浸模式相关消息类型

相关文件：

- `lib/core/models/chat_model.dart`
- `lib/core/database/tables.dart`

沉浸模式使用普通聊天系统的消息表，但扩展了专用消息类型：

```dart
scene      // 场景描述，用于生成或切换背景
narration  // 旁白
options    // 互动选项
```

同时复用已有基础类型：

```dart
words      // 对话
action     // 动作
thought    // 内心想法
state      // 状态
```

### 7.2 消息持久化

奔现消息存储在 `ChatMessages` 表中，通过 `type` 区分消息类型，通过 `sessionId` 关联到聊天会话。

关键字段包括：

```dart
id          // 消息 ID
sessionId   // 会话 ID
isMe        // 是否用户发送
sender      // 发送者
type        // MessageType
content     // 消息内容
messageData // 二进制数据
timestamp   // 时间戳
metadata    // JSON 元数据
isRead      // 是否已读
```

### 7.3 当前数据设计判断

当前没有单独的“奔现场景表”，而是复用聊天会话和聊天消息系统。

优点：

- 集成成本低。
- 可以直接复用角色、聊天历史、消息存储和历史记录能力。
- 奔现可以自然成为某个角色会话的一部分。

潜在问题：

- 普通聊天消息和奔现消息混在同一个会话中，需要靠消息类型区分。
- 如果后续要做独立的奔现场景存档、章节、地点状态、进度恢复，可能需要额外表结构。
- 历史恢复时需要从消息流中还原当前场景状态，逻辑会变复杂。

## 8. 场景图生成与缓存

### 8.1 场景缓存服务

相关文件：

`lib/core/services/scene_cache_service.dart`

`SceneCacheService` 负责避免重复生成同一场景图。

### 8.2 缓存匹配逻辑

缓存根据以下字段匹配：

```text
sessionId + location + time + weather
```

含义：

- 同一个会话下；
- 同一个地点；
- 同一个时间段；
- 同一个天气；

则可以复用之前生成的场景图。

### 8.3 缓存数据模型

```dart
class SceneCache {
  final String id;
  final String sessionId;
  final String location;
  final String time;
  final String weather;
  final String description;
  final String imagePath;
  final int createdAt;
}
```

### 8.4 图片生成流程

```text
AI 返回 scene 消息
  ↓
ScenarioProvider._handleSceneMessage()
  ↓
读取 location / time / weather / content / generate
  ↓
SceneCacheService.findMatch()
  ├─ 命中缓存 → 使用缓存 imagePath
  └─ 未命中或 force → 调用 ImageGenerationService.generateImage()
        ↓
      保存图片文件
        ↓
      写入 scene_cache
  ↓
更新 currentSceneImage
  ↓
ScenarioScreen 背景切换
```

### 8.5 场景生图风格

场景图生成强调：

- 第一人称视角。
- 竖屏构图。
- 真实空间感。
- 与时间、天气、地点一致的光照。
- 如果角色出现在画面中，应面向镜头。
- 避免第三人称、俯视视角、画面中出现“用户自己”。

## 11. 当前可能未完善 / 后续需要重点开发的部分

以下内容不是说完全没有实现，而是从当前架构看，后续继续开发时最值得优先检查和补强。

### 11.1 场景状态恢复

需要确认从历史记录进入场景时：

- 当前背景图是否恢复。
- 当前地点、时间、天气是否恢复。
- 当前角色状态是否恢复。
- 当前互动选项是否恢复。
- 之前生成中的状态是否被正确重置。

建议后续补强方向：

- 从消息历史倒序扫描最近的 `scene`、`state`、`options`。
- 如果缓存图存在则恢复背景。
- 如果图片文件丢失，则展示占位背景或允许重新生成。

### 11.2 奔现会话与普通聊天的边界

当前奔现复用聊天会话和消息表，后续可能需要明确：

- 奔现消息是否同步出现在普通聊天窗口。
- 普通聊天是否应该看到 `scene`、`narration`、`options`。
- 奔现历史是否应该独立于聊天历史。
- 一个角色是否可以有多个奔现场景存档。

如果要做更强的“线下模式”，建议考虑独立 `ScenarioSessions` 或在现有会话上增加场景标识。

### 11.3 场景图生成失败兜底

需要继续验证：

- 图片 API 未配置时如何展示。
- 图片生成失败时是否阻塞剧情。
- 背景图路径失效时是否崩溃。
- 重新生成失败时是否保留旧图。

理想体验：

- 图片失败不阻塞 AI 剧情继续。
- 保留上一张可用背景。
- UI 给出简短中文提示。

### 11.4 Prompt 稳定性

当前依赖 AI 严格输出 JSON。后续需要继续强化：

- 禁止输出多余解释。
- 限制 `scene` 生成频率，避免每轮都重新生成高成本图片。
- 明确什么时候 `generate: true`，什么时候 `generate: false`。
- 让地点、时间、天气字段更稳定，避免缓存失效。
- 约束选项数量和格式。

### 11.5 沉浸感增强

后续可继续开发：

- 角色立绘层。
- 前景人物与背景分离。
- 背景音乐 / 环境音。
- 场景转场动画。
- 角色表情变化。
- 打字机效果。
- 震动 / 触觉反馈。
- 更像 Galgame 的对白框布局。

### 11.6 用户控制能力

可考虑增加：

- 重新生成本轮剧情。
- 只重新生成选项。
- 只重新生成旁白。
- 手动切换场景。
- 手动设定地点、时间、天气。
- 暂停 / 结束奔现。
- 保存为独立记录。

### 11.7 设置项

建议后续补充：

- 是否自动生成场景图。
- 场景图生成模型选择。
- 场景图风格选择。
- 场景图缓存上限。
- 是否显示内心独白。
- 是否显示互动选项。
- 每轮上下文长度。

## 13. 建议的下一步开发优先级

### P0：先保证当前功能可稳定跑通

1. 实机跑通完整链路：发起奔现 → AI 回复 → 场景图生成 → 点击选项 → 继续剧情。
2. 验证没有配置图片生成 API 时是否可用。
3. 验证 AI 返回非标准 JSON 时解析是否可靠。
4. 验证历史记录进入后是否能恢复场景。
5. 验证普通聊天与奔现消息是否互相污染。

### P1：补强沉浸模式的持久化

1. 恢复最后场景状态。
2. 恢复最后互动选项。
3. 场景图文件丢失兜底。
4. 明确奔现记录的数据边界。

### P2：提升体验

1. 优化 UI，让它更像独立线下模式而不是聊天换皮。
2. 加入更明确的转场动画。
3. 增加重新生成剧情/选项能力。
4. 增加场景图风格设置。

### P3：高级沉浸功能

1. 角色立绘层。
2. 背景音乐和环境音。
3. 场景章节 / 多存档。
4. 地图或地点系统。
5. 与角色记忆系统深度联动。

## 14. 总结

当前“奔现 / 线下模式 / 沉浸模式”已经完成了核心功能闭环：入口、页面、状态管理、AI 响应、消息类型、场景图生成、缓存和历史记录都已经有实现。

它现在更像一个“已经能运行的第一版沉浸式场景系统”。后续继续开发时，重点不应再从零搭架构，而应围绕三个方向推进：

1. **稳定性**：历史恢复、失败兜底、JSON 稳定解析、图片生成异常处理。
2. **边界清晰**：奔现会话与普通聊天的关系、是否需要独立存档。
3. **沉浸感**：视觉小说式 UI、角色立绘、转场、音效、更多用户控制能力。
